# CONTRACTS — Strict shared interfaces

Use Pydantic models for backend and generate/mirror TypeScript types. Keep all amounts in **integer INR paise or integer INR consistently**; the MVP below uses `*_inr: int`, no float currencies.

## 1. Data shapes (reference Python, implementation may modularize)
```python
from datetime import datetime
from typing import Literal
from pydantic import BaseModel, Field, model_validator

Mode = Literal['LIVE_DATA','SIMULATED']

class EventBrief(BaseModel):
    title: str
    topic: str
    city: str = 'Mumbai'
    timezone: str = 'Asia/Kolkata'
    starts_at: datetime
    ends_at: datetime
    budget_inr: int = Field(gt=0)
    expected_attendance: int = Field(gt=0)
    venue_capacity: int = Field(gt=0)
    guest_count: int = Field(default=2, ge=0)
    mandatory_resources: list[str] = ['catering','av']
    dietary_requirements: list[str] = []
    promotion_requested: bool = True

    @model_validator(mode='after')
    def check_schedule(self):
        if self.ends_at <= self.starts_at:
            raise ValueError('ends_at must be after starts_at')
        return self

class EvidenceRef(BaseModel):
    provider: str            # CRUSTDATA etc.
    source_id: str           # immutable ref/person/company ID
    collected_at: datetime
    claim: str
    support: str             # field/path/URL when available, not invented
    mode: Mode

class GuestCandidate(BaseModel):
    id: str
    event_id: str
    canonical_person_id: str | None
    display_name: str
    current_title: str | None
    company_name: str | None
    relevance_score: float = Field(ge=0, le=1)
    evidence: list[EvidenceRef]
    invitation_status: Literal['DISCOVERED','INVITED','CONDITIONAL','DECLINED','ACCEPTED','CONFIRMED_SIMULATED','CANCELLED'] = 'DISCOVERED'

class VendorOffer(BaseModel):
    id: str
    vendor_id: str
    service: Literal['catering','av','seating','other']
    quantity: int = Field(gt=0)
    capacity: int = Field(gt=0)
    total_price_inr: int = Field(ge=0)
    delivery_by: datetime
    hold_expires_at: datetime | None = None
    dietary_tags: list[str] = []
    status: Literal['AVAILABLE','HELD','CONFIRMED','EXPIRED','CANCELLED'] = 'AVAILABLE'
    mode: Literal['SIMULATED'] = 'SIMULATED'

class VendorOrder(BaseModel):
    id: str
    event_id: str
    offer_id: str
    idempotency_key: str
    status: Literal['CONFIRMED_SIMULATED','CANCELLED','FAILED']
    committed_inr: int
    cancellation_fee_inr: int = 0
    mode: Literal['SIMULATED'] = 'SIMULATED'

class Issue(BaseModel):
    id: str
    event_id: str
    type: Literal['VENDOR_CANCELLED','GUEST_CANCELLED','ATTENDANCE_CHANGED',
                  'HOLD_EXPIRED','BUDGET_EXCEEDED','CAPACITY_EXCEEDED',
                  'TOOL_FAILURE','UNVERIFIED_IDENTITY']
    severity: Literal['INFO','WARNING','CRITICAL']
    status: Literal['OPEN','RECOVERING','RESOLVED','BLOCKED']
    message: str

class ReadinessResult(BaseModel):
    event_id: str
    status: Literal['READY_IN_SANDBOX','NEEDS_RECOVERY','BLOCKED']
    checks: dict[str,bool]
    blockers: list[str]
    evidence_ids: list[str]
    checked_at: datetime

class AuditEvent(BaseModel):
    id: str
    event_id: str
    action: str
    tool: str
    source_mode: Mode
    status: Literal['SUCCESS','FAILED','SKIPPED']
    reason: str
    references: list[str] = []
    timestamp: datetime
```

### Invariants
- Real Crustdata response must be kept distinct from simulated guest behavior; `mode` travels with evidence and all UI cards.
- LLM-created notes are **not** source evidence.
- Every order references an offer and has a unique `(event_id, idempotency_key)`.
- A guest's `ACCEPTED` text response is **not** equivalent to a booked calendar slot.
- `status=READY_IN_SANDBOX` can only be generated by the verifier, not the LLM.

## 2. REST API contracts

### `POST /api/events`
Request:
```json
{
  "title":"AI/ML Orientation", "topic":"Machine Learning and AI startups",
  "city":"Mumbai", "timezone":"Asia/Kolkata",
  "starts_at":"2026-11-12T16:00:00+05:30", "ends_at":"2026-11-12T19:00:00+05:30",
  "budget_inr":25000, "expected_attendance":120,
  "venue_capacity":150, "guest_count":2,
  "mandatory_resources":["catering","av"],
  "dietary_requirements":["vegetarian_option"]
}
```
Response `202`: `{"event_id":"evt_001","status":"PLANNING","run_id":"run_001"}`. Backend may run short demo workflow in background with explicit persisted run state (no unbounded jobs).

### `GET /api/events/{event_id}`
Response:
```json
{
  "event_id":"evt_001", "status":"READY_IN_SANDBOX",
  "brief":{}, "guest_bookings":[], "orders":[],
  "budget":{"total_inr":25000,"committed_inr":19000,"hold_liability_inr":1000,"available_inr":5000},
  "readiness":{"checks":{},"blockers":[]},
  "simulation_mode":true
}
```

### `GET /api/events/{event_id}/timeline?after_id=...`
`{"items":[{"id":"log_1","timestamp":"...","action":"...","source_mode":"SIMULATED","status":"SUCCESS","reason":"..."}]}`

### `POST /api/events/{event_id}/simulate`
Request `{"event_type":"VENDOR_CANCELLED","target_id":"ord_food_a"}` or `{"event_type":"ATTENDANCE_CHANGED","new_count":145}`. Returns `202` with issue ID. **Simulator-only endpoint.**

### `POST /api/events/{event_id}/verify`
Response: `ReadinessResult`; re-read database state; no generated claims.

### `GET /api/events/{event_id}/promotion`
Return poster copy, reel storyboard and schedule, where available, with `status="DRAFT_SIMULATED"`.

**HTTP rules:** 400 invalid inputs, 404 missing event/offer, 409 incompatible/conflicting state, 422 schema validation, 502 third-party provider failure. Never quietly convert `502` to "no guest exists".

Implement only `SimulatedGuestChannel` and `SimulatedVendorChannel` during competition. **Do not enable real channel adapters.**

## 4. Crustdata adapter contract
- Environment: `CRUSTDATA_API_KEY`, `CRUSTDATA_API_BASE=https://api.crustdata.com`, `CRUSTDATA_API_VERSION=2025-11-01`.
- Headers `authorization: Bearer ...`, `x-api-version: 2025-11-01`.
- Implement Person Search and optionally Person Enrich and Company Search/Identify using **documented request/response specs** provided by official docs or on-site engineers. Do not guess endpoint paths, parameter names or identity IDs.
- Normalize response to `GuestCandidate` and `EvidenceRef`; retain raw provider records internally for debugging with sensitive fields redacted.
- API errors must be explicit and observable. Distinguish missing data, rate limiting, auth failure, and malformed response.
- Never send identified real people's contact information to simulator through a network call; map local synthetic behavior using candidate index or hashed ID.

## 5. Recommended SQLite indexes/constraints
- `orders(idempotency_key UNIQUE)`; `guest_messages(message_id UNIQUE)`; `audit_events(event_id, timestamp)`; `guest_candidates(event_id, canonical_person_id)`; `holds(expires_at)`.
- `event_id` FK on every resource.
- Atomic booking transaction: verify availability + budget and insert order under DB lock/transaction before returning receipt.
